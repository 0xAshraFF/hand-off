# Catalog storage and evidence

Production reads `data/catalog.snapshot.json` through a validated cache. Writes use a temporary file and atomic rename, and refuse concurrent replacement. If no validated snapshot exists, APIs fail closed; corrupted input can retain a prior validated cache with a degradation warning. A deployment must retain snapshot changes or publish an updated build.

`migrations/001_catalog.sql` designs the durable Supabase/Postgres source: providers, tools, models, capabilities, regions, routes, source URLs, normalized pricing, price history, free tiers, subscriptions, offers/history, source checks, quality evidence and benchmarks. RLS grants read-only client access and reserves writes for a server service role. Views use security_invoker, and default model routes cannot duplicate a null region.

Apply the migration in Supabase's SQL editor (its anon/authenticated/service_role roles already exist). Generate a reviewed bootstrap with `pnpm catalog:export path/to/catalog.sql`, then apply it server-side. The exporter retains complete raw tool facts in `tools.details`, normalized prices/capabilities/tags, all price and offer observations, and source checks. Observation hashes make repeated imports idempotent. The migration and actual snapshot export are exercised by PGlite tests, including client write denial, constraints, expiry, apostrophe quoting and repeat imports. No live database is provisioned; automatic DB-to-snapshot synchronization is a future integration, not a claimed runtime feature.

A source check distinguishes reachability from successful scoped price parsing. Reachability does not advance lastVerified. A successful parser stores actual observed rates, scope, time and parser version, even when unchanged. Failures append a check and retain previous values/dates. Conditional quotas carry provider eligibility, limits and a paid fallback. Expired, future, unverified and stale offers are excluded; an account-specific expiry cannot be guessed from a global pricing page.

pricingVerified=false means there is no current parsed observation. quality.status=not-tested means no documented task evaluation. An advertised free trial is never assumed eligible. Free local software excludes existing hardware, electricity, setup and any separately licensed model/voice weights. Owned subscriptions cover supported chat interfaces, with account limits, and never imply API credits. Keep all planner and service-role credentials server-side.
