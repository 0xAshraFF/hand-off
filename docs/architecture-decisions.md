# Handoff — architecture decisions & open questions

Status: decisions recorded, build not started.

## Decided

**Data source — layered.** Artificial Analysis Data API for benchmark scores
(Intelligence / Coding / Agentic indices, GPQA, MMLU-Pro), OpenRouter `/api/v1/models`
for live per-provider pricing and availability. Both cached nightly into our own
Postgres; the app never calls either on the request path. Needs a reconciliation rule
for when the two disagree on price — proposal: OpenRouter wins on price, AA wins on
scores, and we store both with a `source` column so a disagreement is visible rather
than silently resolved.

**Stack — Next.js + Supabase.** Fresh Next.js app. Supabase Auth for Google sign-in,
Supabase Postgres for users, saved projects, the cached model catalog, and aggregates.
Deploy on Vercel. Carry over from the current repo: the shape of `ModelOption`, the
`calculateCost` idea (rewritten — see below), and the handoff-generation concept.
Everything else is replaced.

**Privacy — private by default, opt-in to share.** Project descriptions save to the
owner's account only. An explicit "Share to community" toggle publishes. The trends
surface runs on anonymized aggregates: category, models picked, budget band. Never the
raw description unless shared.

**Analyzer — tiered, cheap first with escalation.** A cheap structured-output model
handles clear cases; escalate to GLM-5.3 when confidence is low or the free-text
description is vague. Both paths emit the same strict JSON schema with a validation
retry.

## What the audit found (why this is close to a rewrite)

- `src/data/models.ts` is a hardcoded 11-model catalog frozen at early-2025 vintage.
  Every entry is at least one generation behind as of Sept 2026.
- `avgLatencyMs`, `tokensPerSec`, and `reliabilityPercent` are invented numbers with no
  source. The GLM entry lists $0.60/$1.80; real GLM-5.3 is $1.40/$4.40.
- Nothing in the codebase reads a benchmark. "Best model" is eight hardcoded
  `if (model.id === ...)` lines plus a strategy-to-default-model switch
  (`server.ts:308-322` and `server.ts:545-555`).
- `server.ts:39` advertises the engine as "GLM-5.3 Fast Frontier Optimizer" and the
  generated spec doc says "Generated By: GLM-5.3". The actual call at `server.ts:506`
  is `model: 'gemini-3.8-flash'`. This claim has to go.
- `calculateCost` returns 0.00 for free and local tiers, so free always wins on price.
  It ignores cached-input pricing (GLM-5.3 cached input is $0.26 vs $1.40 — a 5x swing)
  and ignores reasoning tokens, which dominate output cost on thinking models.
- Token estimates come from asking the LLM to guess. Every downstream budget number
  inherits that error, uncalibrated.
- `communityStore` (`server.ts:22`) is an in-memory array capped at 50, wiped on
  restart, seeded from fabricated preset data. No auth, no users, no persistence.
- `POST /api/community` accepts any JSON with a truthy `projectName` and unshifts it.
  No auth, no rate limit, no validation. Trivially spammable.
- `App.tsx:53-65` fires a full plan generation on mount with a hardcoded marketing
  project, and `ProjectForm` pre-fills the same — every visitor lands inside someone
  else's project.
- `HandoffModal.tsx` and `CachedSetupsModal.tsx` are never imported. Dead code.
- Two design systems collide: App/Roadmap/Header use neutral + black/white, the dead
  HandoffModal uses slate + indigo.
- `tsc --noEmit` currently fails on a missing `vite/client` type definition.

## Open questions

1. **Artificial Analysis terms.** Redistributing their scores inside a public product
   may need permission or attribution beyond the free tier's intent. This should be
   confirmed in writing before it ships, not after.
2. **Who pays for the analyzer calls?** The product is free with Google sign-in. A
   logged-in user can run the wizard repeatedly. Needs a per-user daily cap and a
   cost ceiling, decided before launch.
3. **Escalation trigger.** What concretely signals "low confidence" and promotes a
   request to GLM-5.3? Proposal: schema validation failure, a low self-reported
   confidence field, or a free-text description under ~15 words.
4. **Handoff output format.** `AGENTS.md`, `CLAUDE.md`, and `models.json` are all
   plausible. Proposal is to generate all three and let the user tab between them.
5. **Role granularity.** Recommend per role (planner / bulk worker / vision /
   embeddings) rather than one model per project. Confirm this is the right unit.
6. **Wizard inputs.** Six steps proposed in `claude-design-prompt.md`: project type,
   deployment, modalities, budget, quality/speed/cost weighting, optional free text.
   Confirm the list is right and complete.
7. **Brand.** Does the name "Handoff." survive the rebuild?
8. **Trends tab.** Does it stay as the public-facing data surface, rebuilt on real
   aggregates?
9. **GGUF / local models.** Confirmed as future scope. If it lands, the wizard needs a
   VRAM input to size quants, and Hugging Face becomes a third data source.
