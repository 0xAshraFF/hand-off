Handoff · user flow · 20 Sep 2026

Borrow their chatbot, then hand it back something it could not have told them

The expensive part — breaking a project into tasks — is done by a model the user already pays for, which already knows their project. We take the list it produces, price it against a live catalog, and send back the one thing their assistant would never volunteer: the models that aren't its own.

The whole flow

The excursion out to their own chatbot and back is the distinctive move. Everything after it happens in one backend call.

Inside the one call

The most important rule in the system, and the easiest one to break by accident.

How you would know it brokeYou would not, from testing. A model naming models produces output that looks exactly as plausible as the correct version — right up until someone checks a price against the provider's own page. The only defence is structural: a response schema whose model field is an enum of job types, validated on arrival, with anything off-schema rejected rather than passed through.
