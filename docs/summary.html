Handoff · product summary · 20 September 2026

A prescription for which AI models to use, before you spend anything finding out

You describe what you are building. It tells you which model to use for each task, what it will actually cost in your language, and hands you a document your own chatbot can build from. Free, no account for the main path.

The problem

If the only names you know are Claude and ChatGPT, you are paying frontier prices for work a model costing one hundredth as much handles perfectly well. The same five-task project runs anywhere from $0.25 to $90 a month depending only on which models you pick.

Your assistant will not tell you this. Not from malice — it simply has a home team and no reason to survey the competition. Ask a chatbot what model to use and you get its own.

Meanwhile the people who do know — that Kimi builds better interfaces, that Haiku is ideal for bulk and useless for a quant engine — learned it by burning hours and money. None of that should have to be earned twice.

How it works

Seven steps. The expensive one is done by a model the user already pays for.

  1. Copy our prompt One button. "Give me a project handoff, task by task."
  2. Their own chatbot decomposes the project It already has the context, it runs on their subscription, and it does the hard part better than any form could. Costs us nothing.
  3. Paste the task list back Parsed into an editable list, up to 12 tasks, so they see exactly what will be sent.
  4. Budget — optional Three doors: a slider if they know, a usage question in human units if they do not, or no ceiling at all.
  5. What language must it work in? Not the interface language. This one changes the answer.
  6. One backend call A cheap model sorts each task into a job type. Our own code then scores last night's catalog and picks. About $0.0005.
  7. Results, then the handoff Every task with a pick, a cheaper option and a stronger one. Then a document, written in their language, assembled in code — ready to paste back where they started.

The rules that settle arguments

The model classifies, the code selects

No language model ever names a model a user sees. Ask one to pick and it answers from training data — stale prices, invented numbers. It returns job types from a closed enum; our scorer does the rest.

Price first, budget second

Nobody can budget for something they have never bought. Show the cost, then let budget filter a number they can see.

Fit, not ranking

Every model gets a "shines at" and a "not for". Nothing is a loser. A ranking answers "which is best", which is the wrong question and quietly pushes everyone toward the priciest answer.

Nothing is a ruling

Every pick ships with a cheaper option, a stronger one, and a stated limitation. It is a starting point for exploring, not a verdict that closes the question.

Reduce the asking, never the answer

Fewer questions is always a fair trade. A thinner recommendation never is — the first-timer needs the prescription most.

Prefer the single key

When two models score close, the one on an OpenRouter key wins. The other costs a signup nobody planned for.

What makes it different

Honest evidence
Every recommendation is labelled benchmark-backed, split decision (credible benchmarks disagree, both shown), or hands-on only. No comparison site tells you when it ran out of numbers and started guessing — and that admission is what makes the rest trustworthy.
Real prices
Tokenizers are English-trained, so Bengali, Hindi and Arabic cost 2–4× more tokens for the same content. Every pricing page on the internet quotes the English number. We apply the multiplier, so a $5 budget means $5.
Discovery
Arrive knowing two names, leave knowing nine. Qwen, GLM, Kimi, DeepSeek, Grok, Inkling — surfaced deliberately, counted on the page, because putting unknown names in front of people is the product, not a side effect.
Neutrality
No home team. The survey runs once, across everything, and hands the result back to the assistant they were already using — which is perfectly happy to use those models once told they exist.
Language
The best model for a Bengali support bot is frequently not the English leaderboard leader. Backed by real per-language data for 16 languages, Bangla among them.

What it costs to run

One classification call per recommendation — roughly 1,500 tokens in, 400 out, on a cheap flash model.

ScaleAnnual model spend
10,000 users$33
100,000 users$333
1,000,000 users$3,330
Vercel + Supabase, before a single call~$540

The infrastructure costs more than the intelligence until roughly 150,000 users. So the free-tier cap — three runs a day — exists to stop scripted abuse, not to protect a budget. And most users never reach it: the tile path needs no model call at all.

Shape of the build

Stack

  • Next.js on Vercel
  • Supabase — Google sign-in, Postgres
  • Nightly sync: Artificial Analysis for scores, OpenRouter for live prices
  • Deterministic scorer, no model in the loop

In version one

  • The whole flow, logged out
  • Cloud models across every provider
  • Language-aware picks and pricing
  • Handoff as chat prose, AGENTS.md or models.json
  • A manual lane for models the feeds miss

Deliberately later

  • Hugging Face and GGUF — best differentiator, slowest to get right, must not block launch
  • Accounts and saved plans
  • Images and video — no benchmark backs it
  • Community trends — needs volume to say anything true

Still open

Before building

  • Artificial Analysis terms — redistributing their scores is now load-bearing, not incidental. Confirm in writing.

Before launch

  • Per-user daily cap and a hard spend ceiling
  • Whether the catalog includes subscriptions and tools, not only raw APIs

Worth watching

  • Where people drop off at API-key setup — the one place the handoff hands responsibility back
